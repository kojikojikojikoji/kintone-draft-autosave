# kintone-draft-autosave

English version: [README.md](./README.md)

レコードの作成・編集画面で入力した内容を自動保存し、タブを閉じた後・セッション切れの後・ブラウザのクラッシュ後に復元する。kintoneは未保存の編集内容をサーバーに残さないため、画面が失われると長文の報告や行数の多いサブテーブルを打ち直すことになる。このプラグインはタイマー（既定5秒）でフォームのスナップショットを取り、内容が変わったときだけブラウザのlocalStorageに書き込む。外部サーバーへの送信はない。

デスクトップとモバイルの両方で、作成・編集画面で動く（「レコードの再利用」は作成として扱う）。

## 機能

- 3・5・10・30秒から選んだ間隔で、前回スナップショットから入力に変更があればスナップショットを保存する。
- 保存済みの下書きがあると、フォーム上部にバナーを表示する。内容を確認して復元するボタンと破棄するボタンがあり、確認なしにフォームを上書きすることはない。
- 復元は差分プレビューを通す。下書きと現在のフォームで値が違うフィールドを一覧で示す。
- 下書きはブラウザ・アプリ・レコード・ユーザーごとに分けて保持する。レコードが保存されたとき、または保持期間を過ぎたときに削除する。

## インストール

1. プラグインのzipをビルドする。
   ```
   npm install
   npm run build
   npm run pack
   ```
   `npm run pack` が `dist/plugin.zip` を出力する。初回実行時にはプロジェクトルートに `private.ppk` も生成される（git管理外）。以降のビルドでも同じ `private.ppk` を使い回せば、プラグインIDが変わらない。
2. kintoneでアプリの設定を開き、「プラグイン」から `dist/plugin.zip` を追加して、アプリにプラグインを追加する。
3. アプリを更新して反映する。

## 設定

ラジオボタン2項目のみ。

- 保存間隔: 3・5・10・30秒。既定は5。フォームに変更があったときだけスナップショットを書き込む。
- 下書きの保持期間: 1・24・72時間。既定は24。期限切れの下書きは画面を開いたときに削除する。保持期間の変更が効くのは変更後に保存された下書きで、既存の下書きは元の期限のまま。

## 保存される内容と保存先

下書きはブラウザのlocalStorageに、次の形のキーで保存される。

```
kp-das-<domain>-<appId>-<create|recordId>-<userCode>
```

`userCode` はパーセントエンコードされる。各下書きには、保存可能なフィールドの値、保存時刻、期限、保存時点のレコード更新時刻が入る。フィールドの参照はフィールドコードで保持する。

次のフィールドは保存しない。添付ファイル（中身を保存できない）、計算、レコード番号、作成者・更新者、作成日時・更新日時、ステータス、作業者、カテゴリー、ルックアップのコピー先フィールド（復元するとルックアップ元と食い違うため）。ルックアップはキー値のみ復元するので、コピー先の値はルックアップを再実行して埋め直す。

下書きを消すには:

- バナーのメニュー「保存済みの下書きをすべて削除」で、このプラグインが現在のドメインに保存した下書きを、ユーザーを問わずすべて削除する。
- または、ブラウザでkintoneドメインのサイトデータを消去する。

## 制限事項

- 添付ファイルの中身は保存も復元もしない。フォームに添付ファイルフィールドがある場合、差分プレビューに注記を出す。
- ルックアップのコピー先フィールドは保存しない。キーを復元したら、ルックアップを再実行すること。
- クラッシュ直前の入力は、最後の保存から1間隔分まで失われうる。ブラウザはアンロード時の処理実行を保証しないため、`beforeunload` での保存はしていない。
- 下書きは1台の端末・1つのブラウザに閉じる。端末間の同期はなく、kintoneサーバー側にコピーも持たない。
- 一覧画面のインライン編集は対象外。
- アプリ単位のオンオフ設定はない。止めたい場合はアプリからプラグインを外す。

## プライバシーに関する注意

下書きはブラウザのプロファイル内に暗号化せず保存される。共用PCで同じプロファイルを使うと、後から使う人が前の利用者の下書きを読める。共用機を離れる前に、バナーのメニューで下書きを削除するか、ブラウザのサイトデータを消去すること。プラグインは外部サーバーにデータを送らず、アクセス解析やエラートラッキングのサービスも入れていない。

## 開発

```
npm install
npm run typecheck   # tsc --noEmit
npm test            # vitest, core logic
npm run lint        # eslint
npm run build       # dist/desktop.js, dist/mobile.js, dist/config.js
npm run pack        # build then dist/plugin.zip (generates private.ppk once)
```

純粋なロジック（スナップショット差分、キー生成、スキーマ検証、TTLとサイズの確認、復元時のマージ、時刻フォーマット）は `src/core` にあり、kintoneへの依存はない。単体テストはここを対象にする。DOMとRESTのラッパーは `src/kintone`。`test/e2e` のE2E仕様は開発用のkintoneアプリに対して実行し、接続情報は環境変数（`KINTONE_BASE_URL`、`KINTONE_USERNAME`、`KINTONE_PASSWORD`、`KINTONE_APP_ID`）から読む。

`plugin/icon.svg` を編集した後にアイコンを作り直すには:

```
npm run icon
```

## デモアプリのフィールド

| フィールド | 種類 | 用途 |
| --- | --- | --- |
| タイトル | 文字列（1行） | 基本の保存と復元 |
| 本文 | リッチエディター | changeイベントなしでの保存 |
| 金額 | 数値 | 差分プレビューの表示 |
| 実施日 | 日付 | タイムゾーンの整形 |
| 区分 | ドロップダウン | 選択肢が削除されたときの挙動 |
| 担当者 | ユーザー選択 | 名前の表示 |
| 顧客名 | ルックアップ | ルックアップキーの復元 |
| 顧客住所 | 文字列（1行・ルックアップコピー先） | コピー先の除外 |
| 明細 | サブテーブル（文字列＋数値） | 行全体の復元 |
| 見積書 | 添付ファイル | 注記の表示 |
| 合計 | 計算 | 保存対象からの除外 |
